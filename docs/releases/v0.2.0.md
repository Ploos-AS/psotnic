# Psotnic OCI packaging v0.2.0

Operational release of the Ploos AS container packaging for upstream Psotnic 0.2.14 at commit `b598a8dc25686e2785fb0f9970103cb6a39cdaa6`.

## Changes since v0.1.1

- Added documented main/slave/leaf multi-bot Compose deployment with isolated persistent volumes.
- Added backup and restore helpers, documentation, and an automated backup/restore integrity regression.
- Added documented upgrade and rollback procedures.
- Added CI qualification of persistent state across container recreation.
- Added stable-to-development upgrade and rollback regression using the published v0.1.1 image.
- Added rootless Podman qualification and made publication depend on it.
- Added operations and troubleshooting guidance, including resource-limit examples for small VPS and homelab deployments.
- Added non-invasive configuration preflight checks and regression tests without replacing or reinterpreting upstream Psotnic configuration semantics.
- Extended ownership qualification so persistent state remains compatible with the non-root UID/GID 1000:1000 runtime contract.

## Runtime contract

- Platforms: `linux/amd64`, `linux/arm64`
- Runtime user: `1000:1000`
- Working directory: `/data`
- Persistent data/config: `/data`
- Default config: `/data/psotnic.conf`
- Missing configuration intentionally leaves the container healthy and idle.
- Docker and rootless Podman are qualified deployment paths.

## Upgrade

Before upgrading from v0.1.1, record the deployed image and back up `/data`. CI verifies that persistent state survives an image upgrade to the v0.2.0 code line and rollback to v0.1.1. See `docs/UPGRADE_ROLLBACK.md`.

## Images

The stable release workflow publishes:

- `ghcr.io/ploos-as/psotnic:0.2.0`
- `ghcr.io/ploos-as/psotnic:0.2`
- `ghcr.io/ploos-as/psotnic:latest`

Published multi-architecture images are qualified by digest and include SBOM and provenance attestations.
