# Psotnic OCI packaging v0.1.1

Container packaging release for upstream Psotnic 0.2.14 at commit `b598a8dc25686e2785fb0f9970103cb6a39cdaa6`.

## Changes since v0.1.0

- Added automated runtime qualification for non-root execution, persistent `/data`, lifecycle handling, health state, and invalid configuration behavior.
- Pinned Alpine to 3.22.5 and all reusable GitHub Actions to immutable commit SHAs.
- Hardened Compose and Podman Quadlet deployment contracts with explicit UID/GID 1000:1000, dropped capabilities, and no-new-privileges.
- Added verification of the exact published multi-architecture OCI artifact, including amd64/arm64 manifests, SBOM, and provenance attestations.
- Added image-contract qualification for runtime metadata such as user, workdir, volume, environment, entrypoint, healthcheck, and OCI labels.
- Added release registry integrity checks so the stable `0.1.1`, `0.1`, and `latest` aliases must resolve to the digest produced by the release publish step.

## Runtime contract

- Platforms: `linux/amd64`, `linux/arm64`
- Runtime user: `1000:1000`
- Working directory: `/data`
- Persistent data/config: `/data`
- Default config: `/data/psotnic.conf`
- Missing configuration intentionally leaves the container healthy and idle so configuration can be generated or mounted.

## Images

The stable release workflow publishes:

- `ghcr.io/ploos-as/psotnic:0.1.1`
- `ghcr.io/ploos-as/psotnic:0.1`
- `ghcr.io/ploos-as/psotnic:latest`

Published images are qualified by digest before the workflow succeeds.
